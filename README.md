# 🌾 Farm Game

เกมปลูกผักแบบร่วมมือกัน (สไตล์ Overcooked) เล่นบนเว็บ ทั้งมือถือและคอม — ทุกคนที่เปิดเกมอยู่ในโลกเดียวกัน
ไถ รดน้ำ เก็บเกี่ยว เลี้ยงไก่/วัว แพ็กของ แล้วส่งขึ้นรถให้ทันออเดอร์ก่อนหมดเวลา

- ฉาก 3D สไตล์การ์ตูน (three.js — โมเดลทุกชิ้นสร้างจากโค้ด ไม่มีไฟล์โมเดล)
- เสียงและเพลงสังเคราะห์ในโค้ดทั้งหมด (WebAudio)
- เชื่อมแชทกับห้อง YelloTalk ผ่านบอทได้ (ไม่บังคับ — ไม่ต่อก็เล่นได้ปกติ)

## วิธีเล่น

- **ไม่มีห้อง** เปิดเว็บแล้วเข้าเล่นรอบปัจจุบันได้ทันที เข้ากลางรอบได้ กี่คนก็ได้
- **รอบละ 6 นาที** ทุกรอบเริ่มจากศูนย์ (เงิน ของที่ซื้อ ออเดอร์) จบรอบแล้วได้ดาว ⭐ ตามคะแนน แล้วไปแผนที่ถัดไป
  (ฟาร์มเริ่มต้น → ฟาร์มซากุระ → ฟาร์มทะเลทราย → ฟาร์มหิมะ) เก็บไว้แค่คะแนนสูงสุดของแต่ละแผนที่
- **ถือของได้ทีละชิ้น** — วางบนโต๊ะ/ชั้นวาง โยนให้เพื่อน หรือวางกับพื้น
- **วงจรแปลง**: ไถด้วยจอบ ⛏️ → หยอดเมล็ด → รดน้ำ 🚿 (โตเฉพาะตอนดินชื้น) → เก็บด้วยมือหรือเคียว 🔪
- **ส่งของ**: เอาผลผลิตเข้าเครื่องแพ็ก → ได้กล่อง 📦 → ส่งขึ้นรถให้ตรงออเดอร์ ส่งเร็วได้โบนัส หมดเวลาโดนหักคะแนน
- **สัตว์**: ให้อาหารไก่ 🐔 ได้ไข่ 🥚, ให้อาหารวัว 🐄 ได้นม 🥛 (ไม่ต้องไถ/รดน้ำ)
- **ร้านค้า**: ซื้อเครื่องมือเพิ่ม สปริงเกอร์ 💦 หุ่นไล่กา 🧑‍🌾 และอัปเกรด (บูท ปุ๋ย เครื่องแพ็กไว ฯลฯ)
- **เหตุการณ์สุ่ม**: ฝนตก 🌧 แมลง 🐛 ออเดอร์ด่วน ⚡ ผึ้ง 🐝 ของขวัญ 🎁 ตลาดนัด 🛒
- **ความยากปรับตามจำนวนคนเล่น** — เล่นคนเดียวหรือสองคนจะได้ตัวช่วยเพิ่ม (ออเดอร์น้อยลง ดินชื้นนานขึ้น อัปเกรดฟรี)
- ปุ่ม 💡 เปิดคำแนะนำ "ทำอะไรต่อดี" (ลูกศรชี้เป้าหมาย)

## รันบนเครื่อง

ต้องมี **Node.js 22**

```bash
cd server && npm install && cp .env.example .env
cd client && npm install
```

แล้วเปิดสองฝั่ง (หรือดับเบิลคลิก `run.bat` บน Windows):

```bash
cd server && npm run dev
```

```bash
cd client && npm run dev
```

- เกม: http://localhost:5173
- เซิร์ฟเวอร์: http://localhost:5454 (หน้าอัปโหลดโมเดล/รูป: http://localhost:5454/admin)

ตอน dev ปล่อย `BRIDGE_BOT_ID` ว่างไว้ได้ — หน้าเข้าเกมจะให้พิมพ์ชื่อเอง และแท็บห้อง YelloTalk จะขึ้นว่ายังไม่เชื่อมต่อ

### ตัวแปรใน `server/.env`

| ตัวแปร | ความหมาย |
|---|---|
| `PORT` | พอร์ตเซิร์ฟเวอร์ (ค่าเริ่มต้น 5454) |
| `ADMIN_TOKEN` | รหัสสำหรับอัปโหลดที่ `/admin` — **ต้องตั้งเสมอเมื่อเปิดสู่ภายนอก** |
| `FARM_DATA_DIR` | ที่เก็บ `farm.db` และไฟล์อัปโหลด (ว่าง = `server/data`) |
| `BRIDGE_URL` | ที่อยู่ backend ของบอท YelloTalk (ค่าเริ่มต้น `http://localhost:5353`) |
| `BRIDGE_BOT_ID` | บอทตัวที่จะเชื่อมแชท — ว่าง = ไม่เชื่อมห้อง |
| `BRIDGE_SHOW_ROOM_CHAT` | `true` = โชว์แชทจากห้องในเกมด้วย (ค่าเริ่มต้นไม่โชว์) |

ฝั่ง client มีตัวเดียวคือ `VITE_SERVER_URL` ใน `client/.env` (ที่อยู่เซิร์ฟเวอร์เกม)

## เชื่อมกับห้อง YelloTalk

เซิร์ฟเวอร์เกมต่อ Socket.IO ออกไปหา backend ของบอท (repo `yellotalk-bot-main`, พอร์ต 5353) เพื่อดึง
รายชื่อคนในห้อง ที่นั่งผู้พูด และแชท — แชทที่พิมพ์ในเกมจะถูกส่งเข้าห้องเป็น `🌾 ชื่อ: ข้อความ`
ให้ตั้ง `BRIDGE_URL` + `BRIDGE_BOT_ID` (ดู botId ได้จาก `GET http://localhost:5353/api/bots`)
ถ้าบอทไม่ได้รันอยู่ เกมก็ยังเล่นได้ตามปกติ

## ดีพลอย

- **เซิร์ฟเวอร์ → Render**: New → Blueprint → เลือก repo นี้ (ใช้ `render.yaml`, `rootDir: server`)
  Render จะสุ่ม `ADMIN_TOKEN` ให้ ดูได้ในแท็บ Environment
  แพ็กเกจฟรีไม่มีดิสก์ → คะแนนสูงสุดและไฟล์อัปโหลดหายทุกครั้งที่ restart ถ้าอยากเก็บถาวรให้ใช้แพ็กเกจที่มี disk แล้วตั้ง `FARM_DATA_DIR`
- **หน้าเว็บ → Vercel**: Root Directory = `client`, ตั้ง `VITE_SERVER_URL` เป็น URL ของ Render
  (ค่านี้ฝังตอน build — แก้แล้วต้อง redeploy)
- การเชื่อมห้อง YelloTalk ใช้ได้เฉพาะเมื่อ backend ของบอทมี URL สาธารณะ ไม่งั้นปล่อย `BRIDGE_BOT_ID` ว่าง

## โครงสร้าง

```
server/   Node + Express + Socket.IO + better-sqlite3 — ตัวเกมทั้งหมด (รอบ ออเดอร์ แปลง เหตุการณ์) และ bridge ไปหาบอท
  src/content.js       ข้อมูลและค่าสมดุลทั้งหมด: พืช สัตว์ เครื่องมือ แผนที่ ร้านค้า ความยากตามจำนวนคน
  scripts/playbot.js   บอทเล่นเกมอัตโนมัติ ใช้วัดสมดุล
  public/admin/        หน้าอัปโหลด .glb/รูป มาแทนโมเดลในเกม
client/   Vite + TypeScript + three.js — กราฟิก UI เสียง และการควบคุม
```

รายละเอียดเชิงลึก (โปรโตคอล socket, กติกาการออกแบบ, วิธีทดสอบ) อยู่ใน [CLAUDE.md](CLAUDE.md)
